# Static deployment eligibility (AWS execution disabled)

`COMPLETED` is historical pipeline status, not deployment authorization. After ordinary completion and commissioning cleanup, the orchestrator attempts a distinct decision. Failure to persist never authorizes deployment. Failed pipelines do not enqueue an event. The owner-only GET `/api/infrastructure/:projectId/deployment-eligibility` exposes decision/reasons, execution, timestamps, and NOT_STARTED AWS status; missing schema returns 503, not eligibility.

## Policy and evidence

The operator must independently approve a private regular owner-owned 0600 JSON file, configured as `DEPLOYMENT_ELIGIBILITY_POLICY_FILE`. There is no browser policy-write endpoint and no default approved policy. Required fields: version 1, approved true, nonempty approvalReference, numeric approvedBy, nonempty id, expiresAt, maxAgeSeconds (1–86400), requireActive false, projects array with projectId/ownerId/repositoryId/repository/branch, stages object keyed SAST/Dependency/IaC/DAST each with an explicit `block` severity array. CRITICAL and HIGH must be blocked; MEDIUM/LOW/INFORMATIONAL behavior is explicitly selected by the administrator. This is a separate deployment policy and does not relax existing scan gates. Active-required policies are unsupported in this phase.

All five completed stages are required, regardless of historical pipeline status. Evidence must be execution/revision/artifact-bound, fresh, internally consistent, with reviews resolved. DAST must be BASELINE and match the successful staging URL. SAST counts must represent classified security vulnerabilities, not maintainability findings; unresolved hotspots/unclassified findings block. Dependency evidence must cover vulnerability inventory and valid SBOM, including explicit zero-manifest coverage when appropriate. Missing evidence or policy yields PENDING_EVIDENCE; explicit failures yield BLOCKED; non-static profiles yield UNSUPPORTED.

The pure evaluator accepts normalized stage snapshots and immutable revision bindings (commit SHA, artifact hash, numeric repository identity, owner/project/execution/branch). Each binding references stage ID and SHA-256 of the complete normalized snapshot. Stored decisions contain only summary counts, fingerprints and references, never raw scan responses. Expiry is bounded by the policy and oldest evidence, not refreshed on duplicate completion.

**Producer integration:** the opt-in webhook provenance workflow now records exact source revisions, immutable static artifacts and append-only stage attestations. See [pipeline-provenance.md](pipeline-provenance.md). Legacy executions remain unbound and cannot qualify. Real scanner/API compatibility and controlled application of migration 017 are still required before activation. No evidence is backfilled.

## Migration / transactions

Migration 017 is prepared, NOT applied. Verify backup, isolated restore, constraints and rollback before separately authorized application. It adds immutable revision bindings and eligibility records plus a durable outbox; no historical rows are backfilled. Composite execution/project foreign keys prevent cross-project linkage. Policy/project/execution/environment plus verified evidence digest is the idempotency key; changed evidence creates a distinct denial and fences earlier pending events. SERIALIZABLE transactions plus a per-project transaction advisory lock serialize transitions; unique constraints prevent duplicates. Decision and eligible-event insertion share one transaction. A serialization abort produces no event; a later explicit callback/reconciliation may safely retry the same key. No automatic pipeline retry is introduced.

Outbox states: pending, claimed, processed, blocked, failed. No worker is registered. Lease primitives are explicitly opt-in, bounded to 60 seconds, use SKIP LOCKED, fence by claim UUID, reject stale settlement, and reclaim expired leases. Expired/policy-mismatched/failed executions are blocked. `processed` settlement is deliberately unsupported until a genuine deployment consumer exists. Claiming is not permission to deploy: a future consumer must independently revalidate ownership, current policy, artifact integrity and security evidence immediately before side effects, including reconciliation of uncertain AWS outcomes.

## Runtime prerequisites

No live schema changes, restart, Terraform/AWS calls or activation flags are performed here. Keep INFRA_REAL_PLAN_ENABLED=false, INFRA_REMOTE_PLAN_AUTHORIZED=false, DAST_ACTIVE_ENABLED=false and apply disabled. Missing migration is visibly blocked. Database concurrency/constraint integration still requires isolated PostgreSQL verification; JavaScript database mocks do not establish actual PostgreSQL behavior. No live or historical deployment is modified.
