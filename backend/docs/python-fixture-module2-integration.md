## Existing Module 2 path

The signed webhook feeds the existing orchestrator: SAST → Dependency/SBOM → IaC → deployment checks/deployment → passive DAST → opt-in authorized Active DAST → normalized findings/reporting. Active execution consumes an atomic single-use execution-bound grant and the live runtime registry entry. SQLi rules map to CWE-89 and XSS rules to CWE-79. Active and baseline records remain distinct, with BLOCKED, FAILED, CANCELLED, TIMED_OUT and CLEANUP_FAILED outcomes.

The orchestrator currently skips passive DAST when no usable staging URL exists; it does not independently require a completed passive record before optional Active execution. This is an existing ordering/evidence limitation, not proof that every earlier stage ran. Deployment/image/SBOM evidence must be checked for the intended execution before approving a real test. No standalone Active scan route was introduced.
