# Execution-bound security reports

STATIC_HTML attestations require retained report bundles. Ordinary non-profile scans retain existing behavior. No historical attestations are backfilled; an attestation without a retained bundle cannot establish deployment eligibility.

Storage defaults to ~/.cloudsentinel/security-reports; SECURITY_REPORT_ROOT may select a private local directory. Root/directories must be owned by the backend OS user, 0700; files 0600. Project/execution/stage/scan identity is server-generated. No browser-supplied path is accepted. Same-identity bundles cannot be overwritten. Pending writes are removed on exceptions; files and directory entries are fsynced and published by atomic rename. A crash can leave a private pending directory or an unreferenced completed bundle; preserve for operator review, never treat as attested evidence.

Limits: 50 JSON files, 10 MiB each, 25 MiB total, 64 KiB manifest on verification. Unsafe paths, symlinks, wrong ownership, malformed JSON, empty bundles and recognizable credentials are rejected. Detection is conservative but cannot prove absence of arbitrary sensitive prose. Reports are not redacted and rehashed: recognizable secrets reject admission, preserving the distinction between original evidence and sanitized derivatives. Do not expose reports through public/static routes.

Sonar API response bodies are captured as text before JSON parsing (not TLS wire bytes), including issue pages, quality gate, hotspots and analysis identity responses. Trivy vulnerability stdout, CycloneDX stdout and config stdout are retained at the existing subprocess-output boundary; Dependency stdout trimming is removed so original JSON whitespace is retained. These are UTF-8 captured stdout strings, not binary OS stream recordings. ZAP report.json is retained as original file bytes before checkout/report-directory cleanup. Staging records are generated verification observations (commit, artifact, local/running image IDs, URL), explicitly not native scanner reports.

Each attestation's reports reference binds project, execution, stage, record ID, commit and artifact hash. Its reportHash is SHA-256 of the stored manifest bytes; manifest entries hash exact stored report bytes. Normalized legacy report hashes are replaced in new snapshots. Private independent verification: securityReports.verify(ref) reads the attestation's exact reports reference; deploymentEligibility also checks reference identity, manifest/report hashes, stage-record fingerprints and protected detail fingerprints before eligibility. Missing/corrupt files yield blocked/pending evidence and cannot queue a deployment. Internal verification is not a public report-download API; any future API must independently check current project ownership.

No migration is required: references reside in the existing immutable attestation snapshot. Migration 017/019 are unchanged. Copy report storage, static artifacts and database backups as a consistent protected recovery set; test restore and verify every reference before resuming eligibility. No automatic expiry/purge is implemented. Removing evidence intentionally revokes verifiability; archive only with authorized immutable storage and an explicit restoration/verification procedure. Do not garbage-collect unreferenced bundles while jobs may be running. Shared-storage/multi-host operation requires separately verified filesystem durability and coordination.

Activation requires authorized backend reload, verified private storage/backup configuration, approved policy, pinned ZAP digest and new execution commit. AWS deployment and Active DAST remain disabled. No guarantees about old reports that were already discarded.
